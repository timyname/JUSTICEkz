# JUSTICEkz: пакетная обработка документов дела

## Цель

Добавить в локальный кабинет дела последовательную обработку нескольких документов с прозрачными статусами, извлечением текста, OCR для изображений, выделением датированных событий и отображением результата в браузере.

## Границы

- Поддерживаются TXT/MD/CSV/JSON, текстовые PDF через `pdftotext`, DOCX через встроенный ZIP/XML-разбор, изображения через локальный Tesseract `rus+kaz`.
- Старый DOC обрабатывается через установленный `soffice`/LibreOffice или получает явный статус `converter_pending`.
- Очередь выполняет одну задачу за раз; оригиналы и извлечённые фрагменты остаются в `.justicekz`.
- Каждое событие принадлежит `case_id` и документу, имеет дату, точность даты, страницу и статус `suggested/confirmed/rejected`.
- Автоматические события являются предложениями. Они не считаются подтверждёнными фактами без проверки пользователем.

## Поток

1. API принимает массив документов и сохраняет оригиналы.
2. Для каждого файла создаётся запись со статусом `queued` и прогрессом.
3. Последовательный обработчик извлекает текст или запускает OCR, разбивает текст на фрагменты и пишет их только в память текущего дела.
4. Из строк с датами формируются предлагаемые события хронологии с ссылкой на документ и страницу.
5. API дела возвращает список документов, события и вопросы контроля; браузер показывает статусы и прогресс.

## Надёжность

- Ошибка одного файла не останавливает остальные файлы пачки.
- Недоступные внешние инструменты не маскируются под успешное чтение.
- Миграция SQLite добавляет новые поля к существующей локальной базе без удаления данных.
- В Git не попадают оригиналы, OCR-результаты, база, ключи или веса модели.
