# JUSTICEkz: локальный нейроюрист

## Цель

JUSTICEkz — публичный, но privacy-first проект локального помощника по праву Республики Казахстан. На первом этапе он помогает с гражданскими и экономическими делами, исполнительным производством и спорами с ЧСИ. Система работает через браузер на одном компьютере, хранит документы и память локально, а правовую базу отделяет от памяти конкретного дела.

## Ограничения первого релиза

- Компьютер: Windows, 4 ГБ RAM, Intel Pentium N4200, без дискретной GPU.
- Обязательные сервисы: только Node.js и SQLite, встроенные в Node.js 24.
- Модель подключается через локальный OpenAI-совместимый endpoint, например llama.cpp или Ollama; без модели приложение сохраняет поиск, импорт и структурированный offline-ответ.
- Сканирование использует установленный Tesseract, если он найден. Если OCR недоступен, файл сохраняется, а пользователь получает понятный статус.
- Реальные документы, OCR-тексты, ключи и сопоставления персональных данных не входят в Git.

## Две изолированные памяти

### Общая правовая память

Правовые документы хранятся как версии с названием, типом, номером, источником, URL, датами действия и текстом. Поиск возвращает только редакции, действовавшие на выбранную дату. База не зависит от дела и доступна всем проектам в локальном хранилище.

### Память дела

Каждое дело имеет собственный набор этапов: досудебка, жалоба на ЧСИ, иск, подготовка к заседанию, решение, апелляция и дополнительные этапы. Документы, факты, сообщения, задачи и хронология получают `case_id`; поиск по делу никогда не использует документы другого дела.

Документ сначала попадает во входящие. Система предлагает этап и тип, но перемещение и фиксация факта требуют подтверждения пользователя. Автоматическое резюме помечается как черновик.

## Поток документа

1. Браузер передаёт файл в локальный API.
2. Оригинал сохраняется в локальном каталоге данных дела.
3. Для текстовых файлов извлекается UTF-8-текст; для PDF и изображений вызывается внешний инструмент, если он установлен.
4. Текст разбивается на небольшие фрагменты с номером страницы и метаданными.
5. Фрагменты добавляются в SQLite FTS5 с типом памяти `case`.
6. Контекст чата формируется только из активного дела, его этапов и правовых фрагментов, отфильтрованных по дате.

## Приватность и обезличивание

Перед внешним запросом пользователь видит локальный предпросмотр. Правила заменяют известные стороны, адреса, телефоны, email, ИИН/БИН и похожие идентификаторы на стабильные токены вроде `Юрлицо 1` и `Адрес 1`. Соответствия сохраняются только локально в зашифрованном виде под ключом из локального каталога. Внешний запрос по умолчанию выключен.

## Интерфейс

В браузере доступны:

- список дел и создание дела;
- выбор активного этапа;
- импорт файлов и вставка текста;
- чат с датой правового анализа;
- список найденных источников;
- задачи и вопросы для уточнения;
- подготовка Markdown/HTML и DOCX-документа.

## API и расширяемость

Сервер предоставляет JSON API для дел, этапов, документов, поиска, чата, обезличивания и экспорта. Модель подключается через адаптер, поэтому пользователи могут выбрать локальный llama.cpp, Ollama или другой OpenAI-совместимый endpoint. База и приватные данные не зависят от поставщика модели.

## Надёжность

- В каждом ответе различаются правовые источники, документы дела и предположения.
- При отсутствии модели приложение не придумывает юридический вывод, а показывает найденные фрагменты и список уточнений.
- При отсутствии OCR приложение не скрывает ошибку и не считает нераспознанный скан прочитанным.
- Экспортированные документы считаются черновиками и содержат предупреждение о проверке юристом.

## Версия результата

Первый релиз — локальный MVP: рабочий кабинет, раздельные памяти, FTS-поиск, версии правовых документов, импорт текстовых файлов, подготовка контекста, обезличивание, offline-ответ и DOCX/HTML-экспорт. Полная синхронизация официальных источников, качественный OCR, Google Docs и сложное юридическое рассуждение подключаются отдельными модулями.
